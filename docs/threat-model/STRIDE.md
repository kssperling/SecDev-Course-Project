## Обоснование покрытия STRIDE

### Spoofing (S)
- **F1, F4**: Угрозы подделки идентичности через компрометацию токенов
- **F2**: Риск подделки административных credentials

### Tampering (T)  
- **F1**: Изменение данных в транзите и на клиенте
- **Validation**: Обход бизнес-логики валидации

### Repudiation (R)
- **STORE**: Отсутствие доказательств операций с данными
- Отсутствие audit trail для критичных действий

### Information Disclosure (I)
- **F5**: Утечки между пользователями и при рестарте
- **F3**: Информация об ошибках аутентификации
- Чувствительные данные в памяти приложения

### Denial of Service (D)
- **F1**: Атаки на доступность API
- **APP**: Исчерпание ресурсов приложения

### Elevation of Privilege (E)
- **AUTH**: Обход механизмов авторизации
- **F2**: Доступ к административным функциям

## Ключевые риски

1. **Статические токены** (F4) - высокий риск компрометации
2. **In-memory хранилище** (F5) - риски утечки и потери данных  
3. **Отсутствие rate limiting** (F1) - уязвимость к DoS атакам
4. **Недостаточный аудит** (STORE) - сложность расследования инцидентов

Все контроли согласованы с NFR из P03 и могут быть верифицированы через автоматизированные тесты и мониторинг.

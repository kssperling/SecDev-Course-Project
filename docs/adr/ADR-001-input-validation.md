# ADR-001: Валидация загружаемых файлов
Дата: 2025-10-15
Статус: Accepted

## Context
В нашем сервисе управления персональной библиотекой пользователи могут загружать обложки для книг и статей. Без proper validation возможны:
- Загрузка исполняемых файлов под видом изображений (маскировка вредоносного ПО)
- Path traversal атаки для доступа к системным файлам
- DoS атаки через загрузку очень больших файлов
- Симлинк-атаки на файловую систему сервера

Текущая реализация не проверяет фактическое содержимое файлов, полагаясь только на MIME-типы от клиента.

## Decision
Реализовать многоуровневую валидацию загружаемых файлов:

1. **Magic bytes verification** - проверка сигнатур PNG/JPEG файлов
2. **Лимит размера** - максимальный размер 5MB
3. **Безопасные имена** - генерация UUID + расширение по реальному типу
4. **Path traversal protection** - разрешение и проверка путей
5. **Симлинк проверка** - запрет симлинков в пути сохранения

Конкретные параметры:
- Максимальный размер файла: 5_000_000 байт
- Разрешенные типы: image/png, image/jpeg
- Формат имен: UUIDv4 + соответствующее расширение (.png/.jpg)

## Alternatives
Рассмотренные альтернативы:

1. **Использование библиотеки python-magic**
   - Плюсы: более точное определение типов, поддержка многих форматов
   - Минусы: внешняя зависимость, сложнее установка в разных окружениях

2. **Проверка только по расширениям файлов**
   - Плюсы: простая реализация
   - Минусы: легко обойти, ненадежно

3. **Отказ от валидации (текущее состояние)**
   - Плюсы: нет накладных расходов
   - Минусы: высокий риск безопасности

Выбрана собственная реализация как оптимальный баланс между безопасностью, производительностью и простотой поддержки.

## Consequences
**Положительные последствия:**
- Надежная защита от подделки типов файлов
- Предотвращение path traversal атак
- Контроль использования дискового пространства
- Стандартизированный процесс загрузки файлов

**Отрицательные последствия:**
- Дополнительная обработка каждого файла (проверка сигнатур)
- Возможные ложные срабатывания на корректных но нестандартных файлах
- Необходимость поддержки кода валидации

**Компромиссы:**
- Баланс между безопасностью и производительностью
- Баланс между точностью и сложностью реализации

## Security Impact
- **Снижает риски:** R3 (утечка данных), R5 (раскрытие информации) из P04 Threat Model
- **Соответствует NFR:** NFR-SEC-02 (валидация входных данных), NFR-SEC-03 (защита данных)
- **Устраняет угрозы:** Information Disclosure через загрузку файлов

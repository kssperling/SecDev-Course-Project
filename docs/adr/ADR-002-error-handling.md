# ADR-002: Стандартизация формата ошибок по RFC 7807
Дата: 2025-10-15
Статус: Accepted

## Context
Текущая реализация API возвращает ошибки в различных форматах:
- Некоторые ошибки возвращаются в кастомном JSON формате
- Другие используют стандартные HTTP статусы без деталей
- Нет единого подхода к трассировке запросов

Это приводит к:
- Сложностям в обработке ошибок на стороне клиента
- Возможному раскрытию внутренней информации (information disclosure)
- Трудностям при отладке проблем в production

## Decision
Принять стандарт RFC 7807 "Problem Details for HTTP APIs" для всех ошибок API.

Формат ответа об ошибке:
```json
{
  "type": "about:blank",
  "title": "Validation Failed",
  "status": 422,
  "detail": "Invalid input data in field 'title'",
  "correlation_id": "123e4567-e89b-12d3-a456-426614174000"
}
```

Ключевые аспекты реализации:
- Все ошибки возвращаются в едином формате
- `correlation_id` для трассировки запросов в логах
- Маскирование внутренних деталей реализации
- Консистентные HTTP статус коды
- Поддержка расширений для специфичных ошибок

## Alternatives
Рассмотренные альтернативы:

1. **Кастомный формат ошибок**
   - Плюсы: полный контроль над структурой
   - Минусы: фрагментация, сложнее для клиентов, изобретение велосипеда

2. **GraphQL-style errors**
   - Плюсы: богатые возможности для ошибок
   - Минусы: избыточно для REST API, сложнее клиентам

3. **Оставить текущую реализацию**
   - Плюсы: нет миграционных затрат
   - Минусы: проблемы безопасности и UX, нестандартизированный API

Выбран RFC 7807 как индустриальный стандарт для REST API.

## Consequences
**Положительные последствия:**
- Стандартизированный и предсказуемый API
- Улучшенная безопасность (меньше information disclosure)
- Упрощенная отладка через correlation_id
- Лучший developer experience для клиентов API

**Отрицательные последствия:**
- Необходимость миграции существующих клиентов
- Дополнительные overhead на генерацию UUID для каждого запроса
- Усложнение кода обработки ошибок

**Компромиссы:**
- Баланс между стандартизацией и обратной совместимостью
- Баланс между детализацией ошибок и безопасностью

## Security Impact
- **Снижает риски:** R5 (information disclosure) из P04 Threat Model
- **Соответствует NFR:** NFR-SEC-05 (безопасная обработка ошибок)
- **Устраняет угрозы:** раскрытие внутренней структуры приложения через сообщения об ошибках
